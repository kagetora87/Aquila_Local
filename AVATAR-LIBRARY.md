# Avatar selection and Mira — Aquila Local 1.6

Open **Avatar…**, select **Mira · bundled**, then enable and **Apply / open** (or Restart). Mira is the default for profiles without an explicit avatar selection. **Aquila Guide · bundled** remains available. Enabling is still opt-in; the update preserves user settings. The renderer is bundled and runs locally, without installing Godot or another avatar application.

To use other characters, unzip the download to a folder first. Choose **Choose folder…** to list up to 200 `.vrm` files directly inside that folder. Select a model and Apply / open. **Refresh** discovers newly added files. **Choose file…** selects a VRM directly and uses its containing folder. Files remain in their original locations and are not copied into Data. Keep the chosen file available. Folder and selection persist only when Apply / open, Restart or Stop is pressed. Stop disables reopening; it does not delete any avatar.

Switching characters restarts only the avatar child; chat and the LLM remain independent. Changing camera/FPS for the same running file updates presentation without reopening the model. If a file at the same path was edited, use Restart to reload it. Missing/invalid selections are explained before stopping the current avatar. A file that passes preflight but fails native import closes its failed child and reports the failure; choose the guide or another model to recover.

Supported inputs are self-contained binary VRM 1.0 files, up to 128 MiB, with metadata up to 4 MiB and humanoid hips/head mappings. VRM 0.x needs conversion/re-export. ZIP files and loose FBX/Unity projects are not inputs. External texture/buffer paths are rejected; textures must be embedded. Checks bound obvious format problems but do not certify every third-party model, shader or extension. Rendering is isolated in the optional child process.

The dropdown shows the asset name, creator, size and availability of blink/aa presets. Each model retains its creator's licence and usage restrictions; buying/downloading a model does not automatically permit redistribution inside an app. Mira's source, original README, embedded metadata and notice are retained under **licenses/**. Its source ZIP is preserved in **avatar/Mira-vrm.zip**. The runtime model is **avatar/Models/Mira.vrm**.

## Implementation and compatibility fix

`AvatarCatalog.cs` resolves portable built-in identities and absolute external paths. Empty selection means the current bundled default (Mira when present); `builtin:guide` selects the original guide. `AvatarFolder` and `AvatarModelPath` are saved settings preserved by normal main-window saves. The avatar dialog enumerates the chosen folder and passes the explicit selection to MainWindow.Avatar/AvatarHost. The host validates it before replacing a running child, then supplies its absolute path through the child environment rather than command-line text. The authenticated state protocol is unchanged.

`AvatarShared/AvatarModelFile.cs` performs bounded GLB/VRM metadata inspection in both WPF and the exported renderer. It reads only the header/JSON for validation, not arbitrary asset URLs. Texture/mesh decoding happens in Godot. The rendering process revalidates the selected file before loading it.

`VrmLoader.gd` registers VRM extensions in dependency order, ahead of Godot's mesh converter. First-priority registration prepends, so registrations are reversed to produce the correct execution order. It retains embedded image data uncompressed and disables StandardMaterial texture-channel remapping because MToon uses original glTF slots. This avoids running spring import before the skeleton is prepared and retains original texture addressing.

There is one local patch to pinned godot-vrm revision `e15199f980064028bfa4fbee5e70dddb82dd55c3`: **addons/vrm/1.0/VRMC_vrm.gd**, in `_import_post`, accepts an opt-in `aquila/preserve_bind_pose` state flag. In that mode it normalizes bone names without the addon's axis/rest retarget pass. The default upstream behavior remains when the flag is absent. The original retarget path distorted Mira's skin under the current Godot runtime; retaining the original bind/rest transforms fixes it. This local patch must be retained or revalidated during importer upgrades. The original pinned addon archive and licence are retained.

The motion controller preserves the head's original rest orientation and lowers humanoid upper arms toward a neutral pose using their world rest direction. It does not rewrite the asset. Blinking, breathing, small head motion and speaking-preview mouth shapes remain procedural. This is the model-selection slice of the next avatar work; authored body gestures, animation blending, TTS and audio-driven lip sync remain future work. Full external-animation retargeting must be tested separately against this preserved-rest approach.

## Build and verification

Source includes **AvatarAssets/Mira.vrm** and its original README outside the Godot project. Build.ps1 copies them into the runtime Models folder, avoiding an extra imported copy in the PCK. Godot export uses `UseSharedCompilation=false` and disabled MSBuild node reuse so compiler helpers do not hold the headless export open. The application folder includes the exported runtime; users need no build tools.

`--verify-avatar-library <fresh-evidence>` runs 20 isolated checks: exact default metadata, facial presets, portable identity, folder enumeration, external/saved paths, persistence, path bounds, invalid/old formats, external URI rejection, actual exported Mira/guide/external-file loading, invalid-selection preservation, five acknowledged states, error-free imports and process cleanup. Existing suites add 170 checks, including real chat with Mira enabled/disabled, memory/vision/thinking, conversation management and abrupt-parent-exit cleanup. Native UI and viewport observations are in **verification/UI-CHECKS-1.6.md**; current automated evidence is **verification/v1.6-*/**.
