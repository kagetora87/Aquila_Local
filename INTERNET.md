# Internet access — Aquila Local 1.7

Open **Internet…** in the sidebar. Choose **Off**, **Ask first**, or **Automatic**, and Save. Existing profiles default Off until configured. Automatic performs lookups while answering, not while idle or in background conversations. Ask first shows the exact query or URL and defaults to No for each logical lookup. A declined request is not sent. Off creates no web session or web tools for that turn.

General web search uses **Brave Search API**, configured with an API key from https://api-dashboard.search.brave.com. Enter the key directly in the app's masked field. Leave it blank to retain an existing credential; the remove checkbox clears it. The provider's plan and quotas apply. No account, key creation or billing subscription is performed by Aquila. Public HTTP/HTTPS page reading works without a search key when a web mode is enabled.

Queries go to Brave and page requests go to websites. LLM inference stays local. The key is encrypted using Windows DPAPI for the current Windows user in settings, never sent to the LLM, included in a URL, or forwarded to arbitrary pages/redirects. Moving Data to a different Windows account may require re-entering the credential. Chats, retrieved excerpts and lookup activity are saved locally in the ordinary Data folder; these are not encrypted by Aquila. Automatic queries are chosen by heuristics/model judgment; use Ask first to review outgoing content. Obvious credential-assignment patterns are rejected, but this is not a comprehensive sensitive-data detector.

## Lookup behavior

Agent extends the existing workspace-tool loop with **web_search(query)** and **web_read(url)**. The LLM can choose them when current/unfamiliar information or verification would help, even if the user did not explicitly request a search. Short typed questions containing freshness cues (latest, today, price, weather, news, etc.) receive an initial search; supplied HTTP/HTTPS links receive an initial page read. Other research choices are left to the model. Short ordinary chat does not force a search. Explicit phrases such as "don't search" or "answer offline" disable web tools for that turn. These are English-oriented heuristics, not perfect semantic intent detection.

Only the typed question is used for the automatic initial search, capped at 300 characters. Retrieved memories, attachments and workspace contents are not automatically sent as a query. The model is instructed not to send private data in later tool calls and to treat website text as untrusted reference data, not instructions to use tools or disclose information. This reduces prompt-injection exposure but does not guarantee model judgment or source truthfulness. Internet access does not increase the underlying model's reasoning capability.

Search returns up to five titles, source URLs and short snippets. A snippet is labeled as a snippet, not as full-page verification. Reading extracts bounded plain text from a static HTML/text response, stripping script/style/noscript/SVG markup. It does not execute JavaScript, sign in, submit forms, download binary documents, or automate a browser. UTF-8 text is supported. Paywalls, challenges, dynamic pages, non-UTF-8 text, cookie/session-dependent pages and unsupported content types can fail or yield incomplete text. Failures/timeouts are reported to the model rather than fabricated as results.

Activity displays search/read actions and failures. Retrieved sources persist on Turn.WebSources with titles, URLs, bounded excerpts and UTC retrieval timestamps. The answer gets an app-generated Sources consulted footer containing actual returned URLs even if the model omits citations; it distinguishes search snippets from page evidence. Basic Markdown HTTP/HTTPS source links are clickable and open the user's default browser only on click. Model-generated citations/claims still require judgment; the footer does not prove that every claim is supported. No image, HTML or JavaScript is executed by the chat renderer.

## Bounds and network isolation

At most six logical web lookups occur per turn, inside the existing eight-round/24-tool-call limits. Each page may follow up to five validated redirect attempts. Responses are limited to 1 MiB after HTTP decompression, excerpts to 7,000 characters, and each HTTP operation has a 25-second timeout plus turn cancellation. Search query/URL/argument limits bound serialization. There is no persistent browser or continuous crawler.

Only public HTTP/HTTPS with default ports and no embedded credentials is accepted. Localhost, common private/loopback/link-local/shared ranges, file/data URLs and custom ports are rejected. DNS answers are checked again in the connection callback and the socket connects directly to a permitted address, preventing a separate unchecked DNS resolution. Redirect targets are revalidated. Ambient cookies and proxies are disabled. Search authentication is sent only to the fixed Brave endpoint; provider redirects fail without forwarding it. This is a read-only public-web client, not a general network or browser sandbox.

Web tools share normal model usage accounting: fetched context and additional tool rounds increase session tokens. Network requests themselves are not LLM tokens. Provider request accounting/quota is separate. Cancellation and save behavior follow the existing chat pipeline. Source excerpts do not become cross-chat memories; automatic learning still extracts only supported facts from the typed user message.

## Verification

`--verify-web <fresh-evidence> <small-model.gguf>` runs 32 checks with synthetic settings/chats and CPU-only Qwen3 (two threads). It covers nonpublic addresses, unsupported/credentialed URLs, HTML cleanup, bounded excerpts/freshness cues, per-message opt-out, obvious-credential rejection, Off and denied Ask-first behavior, missing-key explanation, DPAPI/persistence, fixture provider parsing and credential destination, source deduplication, lookup limits, actual HTTPS reading from example.com, a real model answer with proactive URL retrieval/source footer, source/usage persistence, clickable safe links including parentheses, and normal WPF settings saves.

Search-provider schema/auth forwarding is verified using a synthetic fixture, not a paid Brave request or a real user key. A live general-web search must be validated after the user configures their provider key. Public-page retrieval and real-model use are live-tested independently. Existing 190 feature checks are rerun for a total of 222. Native settings UI observations and limits are documented separately. All tests use synthetic Data and unload their models afterward.
